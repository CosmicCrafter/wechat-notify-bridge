# 项目文档内容规范：从实际使用出发

**参考规范 · 由 Notify Bridge DOC-02 的实际改进与验收提炼。** 供后续项目按规模选用，不自动成为跨项目 AGENTS 规则，不要求新建同样的目录、平台或 Skill。

## 先决定读者要完成什么

每篇文档先能用一句话回答“谁在什么条件下，用它完成什么”。保留准确清晰的内容；只有发现操作失败、事实冲突、遗漏前提或维护重复才调整。文档数量、长度和目录整齐不是质量证明。

| 类型 | 推荐内容 | 不应承担 |
|---|---|---|
| 教程 | 一个真实场景、前提、连贯步骤、预期结果、最常见失败、结束验收 | 全部参数和所有高级原理 |
| 操作指南 | 已知目标、权限/资源、命令或界面步骤、验证、失败后处理/恢复 | 从头讲整个系统 |
| 技术参考 | 权威接口/配置、类型/默认/约束、返回语义、错误和版本 | 虚构未声明响应，手抄第二套接口事实 |
| 原理说明 | 问题、对象与边界、为什么选择、替代方案/代价、限制 | 逐按钮教程和宣传词 |
| 工程案例 | 实际背景、局限、取舍、实现锚点、复验方法和证据、已知限制 | 将设想、替身和真人结果合并为通过 |

## 写完后用操作检验，而不是只检查标题

教程中的每一步必须有执行位置、前提和可观察结果；含占位符时写明替换方式，不能把演示值写成默认账号。参数失败时给下一步判断，不让读者反复“重试”。副作用命令默认选择 dry_run 或只读检查；真实操作必须另外有授权。

示例按原文提取执行：验证语法、实际请求方法/参数、返回字段及不泄露凭据，不能只搜索某个关键词。相同业务事件的去重键和原请求要稳定；失败、未知、尚未验证与空结果分开表达。不要让示例自动无限重试或新增长期服务。

## 技术事实只保留一个维护源

API 请求事实优先来自路由/模型及 OpenAPI；字段表可以生成，正文解释它不能表达的运行条件。OpenAPI 没有完整 response_model 就写未声明，不凭经验填满响应。配置来自真实解析/部署入口；版本来自清单，而不是到处改字符串猜测。

网页、Markdown、AI 索引、Skill 和下载包从维护源生成。不同用途的公开指纹先标 scope；私有导出加凭据不使公开源指纹等同整个 ZIP 摘要。新增源、资源或用途需要同步输入清单、链接与包检查；不修生成副本掩盖源错误。

## 图表、示例和引用服务于理解

只在图能解释对象边界、时序或状态迁移时使用；正文必须有对应说明，AI/无图环境仍能理解。图按实际实现画，明确只保护哪一层；不要用“架构图看起来复杂”代替工程收益。静态图不加载外部跟踪资源或活动脚本。

外部技术依据用官方原始文档，记录核对日期；命令还需核对实际宿主版本。仓库内实现与测试给具体文件/函数，真实验收给提交、方法和范围。截图不是权限、安装或业务成功的充分证据；不得公开原始密钥、私人聊天或部署配置。

## AI 入口与操作授权

让普通用户只提供根网址。根 HTML 直接可读，并可发现指南、Markdown、OpenAPI、Skill 与 AI 索引；索引从真实文档集合生成。不能要求用户先学习内部格式，也不能保证所有模型自动访问 llms.txt。

公开阅读只传递知识，不授予 API、管理或真实外发权限。模型只需要私有配置路径及脱敏身份结果，受控连接器进程读取凭据；不把文件内容贴入上下文。收到外部消息、卡片选择或阅读规则不自动获得执行命令、审批、扩权或联系其他人的许可。

## 验证、版本和归档

按影响选测试：文案先读回/链接；示例再实际执行；生成链路做源/产物/版本/包完整性；涉及阅读交互再做真实浏览器和无历史 AI。反向场景至少覆盖实际高风险缺口，例如错版本、缺文件、接收说明遗漏和凭据样式，不为测试数量制造案例。

记录 PASS/FAIL/BLOCKED/UNVERIFIED 和适用提交。静态、SDK、本机 HTTP、真实宿主、真人平台、正式环境分别记录；修复失败后重跑相关范围，不关闭守卫。历史文档保留有价值的当时事实，但退出当前操作入口，不能用历史授权操作生产。

## 按项目规模选深度

| 项目 | 足够的起点 | 何时扩展 |
|---|---|---|
| 小脚本/工具 | README：用途、前提、命令、示例结果、限制 | 只有独立维护/发布需求再补贡献与恢复说明 |
| 有 API 的小服务 | 入门路径、接口规范、配置/备份、错误处理和可运行示例 | 多种接入方或复杂生命周期再拆教程/参考/原理 |
| Notify Bridge 这类长期服务 | 角色导航、协议/权限、运维、同源资料包、真实验收与案例 | 按实际缺口补生成与一致性检查，不默认上文档框架或微服务 |
