# 桌面 AI 消息唤醒：实现与验收

更新：2026-10-03。

## 已实现

服务器 1.5.2 增加经客户端身份校验的 `/api/wake/events`：只返回指定启用会话的新入站编号，不读取正文，不标记已读。无游标时返回当前水位，避免首次启用重放历史。

本机实验接收器 `mcp-plugin/server/desktop_relay.py` 复用 Codex 桌面自带应用工具的本机管道，将事件提醒投递给显式绑定的已有聊天。每 3 秒轮询不调用模型；只有新事件才触发聊天。使用 SQLite 保留游标及投递状态，进程锁防止同一队列重复启动；不确定投递暂停等待核查。

配置及限制见 [桌面唤醒接入说明](../mcp-plugin/DESKTOP-WAKE.md)。本机绑定和凭据保存在项目外层私有目录，不能包含在公开源码包中。

不能把 submitted 当作 AI 完成或手机收件证明。微信/网页消息保留来源，引用和附件不获得独立执行权限。仅为用户明确启用的聊天建立绑定，未绑定聊天仍使用主动读取。

## 技术边界

没有可访问的 App Server TCP 端口不意味着桌面没有消息入口：本次可用入口是原装应用工具的宿主本机管道。该内部接口不是官方承诺稳定的外部 API，接收器需要在桌面提供的环境中启动。

不另起 Codex 推理实例，不修改安装缓存，不扫描其他用户管道。当前不支持应用退出后自动启动，云端 MCP Events 的实验进展见下节。桌面忙碌时沿用其原生投递行为，可能进入当前回合；未实现额外的任务完成等待调度。

## 云端 Work 事件试验（2026-10-03）

服务器 1.6.3 新增独立 MCP Events 兼容适配层，保留原有工具及桌面接收器。接口、鉴权、签名回调及回退说明见 [MCP Events](server/MCP-EVENTS.md)。升级前保留 1.5.2 完整源码、旧镜像、旧容器和数据备份。

已验证：网页 ChatGPT Work 实际发现 `message.created` 和必填的 `conversation_id`；独立网页会话登记成功，宿主实际调用了 `events/subscribe`。新增模块初版与现有代码合计 98 项回归通过，新增地址校验及诊断后的事件专项 14 项通过；线上原有 9 个工具、OAuth 及飞书发现检查通过。

尚未接通：生产服务器向 OpenAI 回调主机 `connectors.api.openai.com` 验证时连接超时。服务器系统 DNS 与公开 DNS 结果不一致；通过公开 DNS 返回的地址连接并保留原始 TLS 主机名和证书校验，仍出现连接重置。宿主自动取消失败订阅，未保存事件任务，未进行真实微信到网页 AI 唤醒验收。

下一步需要可正常访问回调主机的服务器出口或受控中转。不要硬编码临时 DNS 地址、关闭 TLS 校验或放宽公网地址限制。接通网络后重新订阅，验证真实入站、自动处理、微信回复及取消订阅；不能把事件发现当作完整唤醒成功。

### 代理接入后的进展（1.6.4）

在现有服务器部署独立代理，仅指定的 OpenAI 回调主机走用户选择的日本 Pro 01 节点。代理只监听内部网桥地址，要求认证，其他目标拒绝；微信与飞书继续直连。节点凭据与订阅链接不纳入源码。

实测：代理下访问回调主机获得 HTTP 响应且 TLS 校验通过；网页 Work 创建事件任务成功并查询确认已启用；服务端保存一条 active 订阅，签名 challenge 验证通过。真实微信触发 AI 和回信验收已通过，见下方记录。该测试任务仅发送固定确认文字，不执行消息中的其他任务。

原 1.5.2 基线与升级前 1.6.3 容器/数据备份保留。代理未配置订阅自动更新；节点凭据或线路变化时需更新私有配置并重启代理。该节点由用户提供，源码使用通用配置，不绑定其个人订阅。
