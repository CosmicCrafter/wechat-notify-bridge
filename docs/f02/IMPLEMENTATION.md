# F02 合同、实施与验收

需求依据：[正式设计基线](F02_正式设计基线.md)，来源摘要见SOURCE.sha256。当前分支codex/upgrade-after-stable-20261014，F02起点81770be，工作树干净。E0～E4、关闭管理Key和共享气泡组件均保留。本轮只授权独立本地开发；禁止生产Bot/数据/部署和main合并。

## F02-0 定向差异与合同

已核对conversations、inbox_claims、clients API、MCP工具/Events、管理与手机归档、飞书入站/出站和现有发送账本。已有同应用多会话、首条消息原子幂等、严格client_id归属和显式领取。缺少会话接收权限、领取租约/代际、独立归档/静音/外部停止、应用与会话通知策略。飞书parent_id已有映射，但无引用时会自动匹配唯一待填任务；新受保护路径不能使用此推断。GET inbox无conversation_id时当前只读未归属消息，并非所有直接消息；同一应用Key仍能逐一指定其他会话，所以没有聊天实例隔离。

### 安全层级与接收绑定

应用Key继续证明client_id。新增受保护会话需要额外X-Notify-Receiver会话接收能力；高熵随机能力只一次签发、服务端只存摘要，限制到conversation_id和主处理者/观察者角色，验证持有后才激活。一个主处理者，观察者只能读。凭据验证证明权限持有，不证明ChatGPT/Codex/Claude具体聊天的身份；绑定返回独立host_identity=unverified，不使用“宿主严格绑定”成功标签。

旧注册默认legacy；新版管理页面主动传protected，首条消息可靠保存并显示待绑定。AI显式注册protected时首次原子签发接收能力，稳定注册键重复请求不会再返回秘密或夺取现有绑定。已有受保护会话必须经管理端配对/换绑；共享应用Key不能自行领走管理端创建的会话。MCP仅在显式配置独立上下文私有接收文件时支持自动保存/提交能力；不能将令牌返回模型或缓存成同应用所有聊天可访问的全局表。没有这种安全保存条件的宿主停在legacy/待绑定，继续可靠入箱，明确限制。

新权限覆盖收件、history、图片、task读取/上报、claim/report、wake/events与发送；元数据查询不等于数据/执行权限。protected路径禁止include_unaddressed和无授权跨会话操作。App Key轮换、撤销及Bot权限每次仍重新校验，不因附加能力绕过原权限。换绑撤销旧能力、订阅和旧领取资格，并记录审计。

### 最小数据与接口增量

- conversations增加receiver_mode与独立archived；旧active=0迁移为archived=1且保持active=0，绝不自动恢复通信。
- receiver_bindings保存角色、摘要、挑战、期限、验证/撤销及宿主声明；绑定审计不含令牌。新增验证、管理员配对/撤销与状态查询。
- inbox_claims附加binding_id、generation、lease_expires；旧记录generation=0/无租约，保留旧报告合同。受保护领取默认120秒，续期与接管显式执行，迟到报告必须带匹配代际。领取/续期/过期接管/完成均有审计。外部副作用仍需执行端用稳定消息ID幂等。
- 新生命周期接口分别控制归档可见性、静音与外部停止命令/回执；沿用现有持久消息账本，不增加内部执行器。收到真正执行端停止回执后才关闭通信及绑定/订阅；缺失回执仅显示待确认或超时未确认。
- 复用MCP Events已有持久订阅和回调挑战，补接收范围校验及到期/失败/撤销状态查询；补查走持久inbox，不将2xx写成执行完成。
- 应用通知默认、会话偏好及管理员授权紧急Bot配置为简单确定性策略，不引入规则引擎。飞书原生引用按同Bot的parent_id映射；新路径无引用不猜任务或会话，进入管理员待归属队列。

### 兼容与通知规则

| 路径 | 保留/新增语义 |
| --- | --- |
| 旧注册与应用Key | 默认legacy，不自动改成protected；同应用可新增多个会话，无需新应用Key |
| 旧state(active)及旧归档请求 | 保留关闭/恢复语义；新UI用visibility_only=true仅改归档可见性 |
| 历史active=0 | 保持停用；取消归档不自动启用，界面说明旧状态 |
| 旧claim/report | 继续原合同；protected要求绑定、租约与generation |
| 显式bot_id/channel | 保留原选择与授权，不被新偏好/紧急路由偷偷覆盖 |
| 未显式目标 | 会话偏好覆盖应用默认；获授权urgent可选择紧急Bot，未授权则拒绝 |
| 静音 | 普通提醒不走平台，正文/任务仍保存；获授权紧急规则可越过静音并明确展示 |
| 结果未知 | 沿原逻辑消息/目标查询，不换Bot重发；备用仅在有明确未发送证据的受控策略下执行 |

新路由选中哪一个Bot、限频/静音、失败与各尝试必须可查询。逻辑消息与业务任务不能因备用投递复制。默认紧急失败策略为保留失败，不自动降级。若实施需要缩小备用范围，记录实际支持条件，不伪报已实现。
