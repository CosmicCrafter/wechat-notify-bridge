# F02 合同、实施与验收

需求依据：[正式设计基线](F02_正式设计基线.md)，来源摘要见SOURCE.sha256。当前分支codex/upgrade-after-stable-20261014，F02起点81770be，工作树干净。E0～E4、关闭管理Key和共享气泡组件均保留。本轮只授权独立本地开发；禁止生产Bot/数据/部署和main合并。

## F02-0 定向差异与合同

已核对conversations、inbox_claims、clients API、MCP工具/Events、管理与手机归档、飞书入站/出站和现有发送账本。已有同应用多会话、首条消息原子幂等、严格client_id归属和显式领取。缺少会话接收权限、领取租约/代际、独立归档/静音/外部停止、应用与会话通知策略。飞书parent_id已有映射，但无引用时会自动匹配唯一待填任务；新受保护路径不能使用此推断。GET inbox无conversation_id时当前只读未归属消息，并非所有直接消息；同一应用Key仍能逐一指定其他会话，所以没有聊天实例隔离。

### 安全层级与接收绑定

应用Key继续证明client_id。新增受保护会话需要额外X-Notify-Receiver会话接收能力；高熵随机能力只一次签发、服务端只存摘要，限制到conversation_id和主处理者/观察者角色，验证持有后才激活。一个主处理者，观察者只能读。凭据验证证明权限持有，不证明ChatGPT/Codex/Claude具体聊天的身份；绑定返回独立host_identity=unverified，不使用“宿主严格绑定”成功标签。

旧注册默认legacy；新版管理页面主动传protected，首条消息可靠保存并显示待绑定。AI显式注册protected时首次原子签发接收能力，稳定注册键重复请求不会再返回秘密或夺取现有绑定。已有受保护会话必须经管理端配对/换绑；共享应用Key不能自行领走管理端创建的会话。MCP仅在显式配置独立上下文私有接收文件时支持自动保存/提交能力；不能将令牌返回模型或缓存成同应用所有聊天可访问的全局表。没有这种安全保存条件的宿主停在legacy/待绑定，继续可靠入箱，明确限制。

新权限覆盖收件、history、图片、task读取/上报、claim/report、wake/events与发送；元数据查询不等于数据/执行权限。protected路径禁止include_unaddressed和无授权跨会话操作。App Key轮换、撤销及Bot权限每次仍重新校验，不因附加能力绕过原权限。换绑撤销旧能力、订阅和旧领取资格，并记录审计。

### 最小数据与接口增量

- conversations增加receiver_mode与独立archived；旧active=0迁移为archived=1且保持active=0，绝不自动恢复通信。
- receiver_bindings保存角色、摘要、挑战、期限、验证/撤销及宿主声明；绑定审计不含令牌。新增验证、管理员配对/撤销与状态查询。
- inbox_claims附加binding_id、generation、lease_expires；旧记录generation=0/无租约，保留旧报告合同。受保护领取默认120秒，续期与接管显式执行，迟到报告必须带匹配代际。领取/续期/过期接管/完成均有审计。外部副作用仍需执行端用稳定消息ID幂等。
- 新生命周期接口分别控制归档可见性、静音与外部停止命令/回执；沿用现有持久消息账本，不增加内部执行器。收到真正执行端停止回执后才关闭通信及绑定/订阅；缺失回执仅显示待确认或超时未确认。
- 复用MCP Events已有持久订阅和回调挑战，补接收范围校验及到期/失败/撤销状态查询；补查走持久inbox，不将2xx写成执行完成。
- 应用通知默认、会话偏好及管理员授权紧急Bot配置为简单确定性策略，不引入规则引擎。飞书原生引用按同Bot的parent_id映射；新路径无引用不猜任务或会话，进入管理员待归属队列。

### 兼容与通知规则

| 路径 | 保留/新增语义 |
| --- | --- |
| 旧注册与应用Key | 默认legacy，不自动改成protected；同应用可新增多个会话，无需新应用Key |
| 旧state(active)及旧归档请求 | 保留关闭/恢复语义；新UI用visibility_only=true仅改归档可见性 |
| 历史active=0 | 保持停用；取消归档不自动启用，界面说明旧状态 |
| 旧claim/report | 继续原合同；protected要求绑定、租约与generation |
| 显式bot_id/channel | 保留原选择与授权，不被新偏好/紧急路由偷偷覆盖 |
| 未显式目标 | 会话偏好覆盖应用默认；获授权urgent可选择紧急Bot，未授权则拒绝 |
| 静音 | 普通提醒不走平台，正文/任务仍保存；获授权紧急规则可越过静音并明确展示 |
| 结果未知 | 沿原逻辑消息/目标查询，不换Bot重发；备用仅在有明确未发送证据的受控策略下执行 |

新路由选中哪一个Bot、限频/静音、失败与各尝试必须可查询。逻辑消息与业务任务不能因备用投递复制。默认紧急失败策略为保留失败，不自动降级。若实施需要缩小备用范围，记录实际支持条件，不伪报已实现。

## F02-1 实施与验证

已增加protected/legacy接收模式、唯一主绑定与只读观察者、一次性管理员配对、挑战验证、到期/撤销/换绑审计。应用认证仍逐次校验原Key/OAuth，额外接收能力仅存摘要；旧API注册默认legacy，新管理端显式protected并先保存首条消息。读/发/history/图片/task/claim/report/wake/events路径按会话能力拒绝跨会话；受保护收件禁止未归属数据，包括true/1/yes/on等布尔别名。绑定验证只能证明能力持有，host_identity始终unverified。

用户于2026-10-15明确确认：取消旧飞书“裸文本自动回答唯一任务”的猜测行为。现在无引用文本保留到待归属队列；输入任务必须引用原卡片才可直接答复，普通引用按同Bot的provider消息映射，名称与引用冲突不转投。管理员可明确归属未知消息，重新检查Bot授权，稳定inbox_id不变且幂等；已直接归属的消息不能改投。受保护会话不再用显示名作为入箱地址，提供稳定conversation标签，微信仍可用已认证会话页精确回复。旧应用级显式标签继续兼容。

MCP登记增加可选protected模式；本地适配器仅在指定独立receiver_file时将首次能力保存并验证，秘密不返回模型，不覆盖应用配置，也不建立全应用的接收秘密缓存。远程MCP缺少已核验私有保存能力时拒绝protected注册，已配对的限定能力可通过HTTP头提交；真实宿主能否安全隔离该文件仍未证明。配对文件不含应用Key，页面只提供私密下载，不在截图或日志显示代码。

实际验证：83项绑定/飞书/Events/旧会话/MCP/stdio定向回归通过；接收与入站9项补充测试通过；私有接收文件与现有导出流程10项通过。验证了旧Key未轮换、旧会话模式保留、受保护库一致备份后重开/解密/权限校验，另保留1项既有anyio警告。浏览器实际新建protected会话、保存首条消息、显示待绑定、生成并下载配对文件；真实stdio MCP SDK用该文件交换并验证后读取/领取/报告，第二个独立SDK进程使用同一应用Key创建A02，读取A01被拒绝。工具结果不含接收秘密，页面验证后仍显示“具体AI聊天身份未验证”。这是真实协议/SDK验证，不能冒充ChatGPT Work/Dot、Codex或Claude聊天的验收。

文件主体：storage/receivers.py、api/receivers.py/inbound_routes.py、既有客户端认证/会话/Events/原生入站、MCP适配器receiver_store.py和共享气泡管理扩展。公开接口文档、SDK拷贝、Vue产物与导出模板同步更新。只更新了原19865隔离进程（平台工厂仍全为替身、收件后台关闭），没有生产访问/部署。回退需与升级前一致快照匹配，旧二进制不能忽略protected权限字段继续使用新库。

F02-1完成，提交见分支同名批次；F02-2租约/三种生命周期和F02-3通知分流尚未实施。

## F02-2 实施与验证

受保护claim默认120秒租约（30～900秒），续期只接受当前binding/claim/generation和仍有效的租约。超时接管沿用inbox_id，递增generation并审计；旧领取者报告、过期续期、旧代际均拒绝。旧应用级记录generation=0/无租约，旧claim/report合同不变；报告正文仍加密。界面单独显示租约过期，不把读到数据、事件送达当成完成。

conversations新增独立archived字段，首次迁移将原active=0的记录归档但保留active=0。新页面使用visibility_only=true只整理列表，原state(active)及未传该标记的旧归档请求保持原关闭合同。取消归档不会复活旧停用会话。运行中的已声明外部监控不能通过旧关闭/删除接口绕过停止确认。

外部接收端可报告running；owner发送结构化stop_monitor命令，正文与控制信息先可靠入箱，重复请求复用同一命令。只有正确主接收者明确领取停止命令并携带当前claim/generation和stop_id回报stopped，才记录“执行端已确认停止”、关闭通信并撤销绑定/订阅。5分钟没有回执只显示超时未确认，允许匹配的迟到回执。physical_execution_verified始终false：系统核验的是授权回执，不是操作系统进程或真实抢票任务状态。

MCP Events继续使用既有挑战、持久状态与有界重试，增加最后验证/投递时间和HTTP状态查询；取消与到期状态留存。归档不撤销订阅，回调失败/到期后消息仍在inbox；取消订阅不等于停止外部程序，客户端通过持久工具补查。管理端可查看/取消订阅，不暴露回调URL或签名秘密。静音独立标记与界面入口已就绪，实际通知抑制随F02-3路由完成，不将状态标记单独当成已经停止发送。

验证：租约与旧会话合同7项通过，生命周期/领取/订阅/Events/旧会话综合25项通过；增加订阅追踪后相关21项复测通过，均有1项既有anyio警告。并发两次领取仅一次成功、超时续期拒绝、代际接管与迟到报告拒绝、一致库恢复保留租约、旧停用状态不误恢复、停止仅影响A而B继续、匹配当前代际才可确认。浏览器实际归档后继续通信并显示执行端报告运行，再发送停止请求显示“待确认”；受控外部测试接收器领取该命令、按代际确认后被撤销收件权限。没有运行真实业务监控或真实宿主。

新增storage/lifecycle.py与api/lifecycle.py，扩展原claim/Events/schema/MCP与共享界面；不引入调度服务。已同步规范、导出模板与构建产物。F02-2完成，实际静音/通知分流和最终全量收口在F02-3继续。
