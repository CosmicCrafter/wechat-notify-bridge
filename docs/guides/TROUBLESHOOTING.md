# 故障排查：先确定失败在哪一层

**操作指南 · 适用服务 1.19.0。** 从一个实际请求、原会话和原去重键开始。不要反复建应用、换 Key、换 Bot 或发新通知来探测。没有相应权限时只收集脱敏证据并交维护者。

## 最短定位路径

| 现象 | 第一个检查 | 再看哪里 |
|---|---|---|
| 不知道如何开始 | 你是管理员、业务开发者还是 AI 宿主使用者 | [第一次接入](../tutorials/FIRST-INTEGRATION.md) |
| 无工具 / stdio 起不来 | Python 版本、绝对路径、prepare 是否成功、是否重复装同名 MCP | [客户端安装](../integration/CLIENT-SETUP.md) |
| 401 / 身份不对 | 实际服务地址、应用 Key/独立 OAuth、client_id | [API 鉴权](../server/API.md#条件性会话接收授权) |
| 403 / protected 内容被拒 | 本会话能力、验证/过期状态、角色与 Bot 授权 | [接收绑定](../integration/RECEIVERS.md)，不删除能力头降级 |
| 409 | 读取具体 detail：关闭、目标不明、去重冲突、租约/代际冲突 | [重试决策](../server/API.md#错误处理与重试决策) |
| 422 | 请求模型和组合约束；占位符不能直接用 | [生成字段合同](../reference/HTTP-CONTRACT.md) |
| API 接受但手机没看到 | 原回执、平台/微信上下文、本人的实际确认 | [投递与诊断](../server/DELIVERY-RELIABILITY.md) |
| 飞书卡片不回传 | 两处回调/订阅是否发布、同应用 Open ID、签名与原任务状态 | [飞书配置](../server/FEISHU.md)；不擅自切共享回调 |
| 文字回复未到会话 | 引用/完整标签、原 Bot、待归属队列、游标、绑定授权 | [会话与收件](../explanations/RELIABLE-CONVERSATIONS.md) |
| AI 没自动回答 | 先判断是否能主动读到；再看真实宿主接收器/订阅 | [事件与唤醒](../server/MCP-EVENTS.md)，安装成功不等于唤醒 |
| 管理端无法登录 | 账号是否初始化、是否用错手机码/应用 Key、恢复连接 | [管理员恢复](../product-v3/OPERATIONS.md) |
| 页面或包内容过时 | 当前服务/插件版本、指纹 scope、源与生成物是否匹配 | [维护构建](../MAINTAINER.md)，不手改 ZIP |

## 超时和结果未知

先保存完整原请求的非敏感业务标识，查询原回执。显式 Bot 保持原目标，策略请求继续省略原目标；不要把返回实际 Bot 补入查询。not_found 也先排查应用/会话/目标范围和在途状态，不直接换键补发。

只有明确 not_sent 且满足飞书准备阶段证据时才按原快照显式 retry_preparation；其余情况由维护者核对后决定。没有新授权，不改通知目标、平台配置或服务网络条件。

## 给维护者什么材料

提供候选/运行版本、发生时间（含时区）、请求方法与路径、HTTP 状态、固定错误分类、会话/消息/任务标识、原目标省略方式、去重键、dry_run 与实际收件事实。日志和截图先脱敏；不发送 Key、Authorization、接收能力、验证码、Bot Secret、完整敏感正文或数据库。

写清哪些实际通过，哪些没有执行。例如“身份和 dry_run 通过，真人收件未验证”，不能写“通知全链路正常”。涉及正式服务切换、回调、恢复或应用权限，先确认当次授权和恢复点；本指南本身不授权操作。
