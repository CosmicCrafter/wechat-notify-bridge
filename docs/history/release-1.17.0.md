# 1.17.0：统一管理端与可靠会话接收

本版交付 v0.3 产品迭代及 F02、F01/F03/F04，业务基线为 `15f4812`。发布整理只更新版本标识、过时账号说明及生成的接入资料，不增加业务功能或升级运行依赖。正式上线状态以实际容器镜像、发布标签和部署记录为准。

## 行为与兼容

- 管理端统一会话、投递、应用、连接和系统设置；管理端与手机端复用气泡会话组件。
- 应用身份与 Key 分离，保留原应用 Key、授权、历史会话及旧 HTTP/MCP 接口；新会话可以使用接收绑定、领取租约和离线补查。
- 共享应用 Key 不证明宿主聊天身份；接收凭据只能证明绑定能力，不声称所有 AI 宿主均能自动唤醒。
- 飞书无明确引用或路由标签的裸文本保留待归属，不再猜测唯一待答任务。这是已确认的旧行为变更。
- 通知分流须显式授权，原默认 Bot 和授权不批量改写，不在失败后猜测另一个投递目标。
- 管理端只接受账号密码会话，原管理员 Key 登录关闭。原部署尚无账号时，使用现有获授权服务器终端工具初始化；无默认密码、无公开初始化/密码重置接口。
- 新建连接待配置时不可投递；凭据保存和真实通信验证是不同状态。

## 升级与回退

1. 先保存当前镜像、容器环境/挂载、原密钥和配置，并通过 SQLite backup API 取得最新一致备份。数据库与原加密密钥必须配套。
2. 在断网、无生产挂载、无端口发布、`run_workers=False` 的副本中实际迁移、解密、检查历史/授权/旧 Key，并验证升级后备份恢复和管理员密码登录。
3. 切换前再次保存最终一致快照；单进程启动候选，保持原端口、代理、OAuth issuer、Bot 配置和回调地址。实际数据路径以 `docker inspect` 挂载为准，不假定历史目录仍是当前运行目录。
4. 失败先封存升级库及新增消息，再用匹配旧代码的独立旧结构目录恢复；不能直接用旧二进制读取升级库。已撤销、到期的旧凭据不能因回退恢复有效。
5. 新增消息、任务处理状态和新 Key 保留在封存库，按平台消息 ID、会话 ID 和任务 ID 对账后另行处理；不自动重发或宣称回退零消息损失。

R3 的生产数据副本升级、恢复、解密、旧 Key 和管理员登录检查已实际执行；原始证据及包含密钥的数据只保存在受保护备份目录。390 项 Python、7 项前端测试通过。真实 Codex 主动调用和飞书双向会话已有专项证据；Claude Code、Work/Dot 自动唤醒及飞书故障后的自然重投仍单独列为未完成，不据此声称所有宿主能力通过。
