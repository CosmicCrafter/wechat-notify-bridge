## 正式上线前检查（须另获授权）

1. 核对最终提交及镜像标识、服务 1.18.0 / 插件 1.11.0；确认 Linux/Windows 托管 CI 对应这个提交，而非旧基线。实际健康版本、公开 RELEASE 与管理端资料版本应一致。
2. 按[维护手册](../MAINTAINER.md)保护最新一致 SQLite、原密钥、配置与旧镜像；保留所有原稳定标签。即使无迁移，也不能在授权外直接替换生产。
3. 只在现有 `/bridge/` 的 HTTPS server 块复用 `server/deploy/nginx.conf` 的反向代理：`/bridge/docs/` 转发到同一候选进程的 `/docs/`，由应用读取固定资产。不要另设 alias/root 指向仓库、数据目录或整个 web/admin。
4. `/bridge/docs` 的相对重定向、HTML 内相对链接、Markdown、OpenAPI、Python、ZIP 都应保留 `/bridge/` 前缀；不新增或重写其他服务的 location、飞书回调、OAuth issuer、旧 `/wechat/` 或根级 discovery。OAuth 保留旧前缀时继续使用导出的 mcp_url。
5. 当前应用对公开及私有响应统一发送 `Cache-Control: no-store`。代理/CDN 不覆盖该头，不缓存 Cookie、Authorization、管理 API、消息、私有导出或错误响应；未版本化的 HTML/JS/CSS/规范/ZIP 不设置 immutable。若边缘已有缓存，发布时只清理本服务相关路径并核验，不清理同域其他业务缓存。
6. 正式 HTTPS 入口应做匿名 GET：HTML/MD/规范/ZIP 为 200、无登录重定向或 Set-Cookie；正文不是旧登录页，RELEASE 为 1.18.0/1.11.0。匿名管理 API、Key、消息和私有下载拒绝，不能仅凭网页登录壳能打开判断数据泄露。
7. 核对 TLS 证书、现有访问控制、MIME、`nosniff`、CSP、`no-store`、路径穿越拒绝及下载无私有配置。隔离 HTTP Nginx 测试不等于正式证书/CDN/公网验收。
8. 获授权部署后再验管理账号登录、现有 Key/MCP、历史消息、双向路由与受控真人收件。Claude/Work/Dot 和自动唤醒不因静态文档验收自动通过；缺少资源须保留未验证项。
