# 手机端的日常使用

通知桥可以接入 AI，也可以接入监控脚本、定时程序和其他应用。普通程序使用 HTTP API；AI 可以使用同一服务的 MCP。以下交互全部按需使用。

## 待我处理

手机会话页的「待我处理」汇总所有有效对话中尚未提交答复的卡片。阅读卡片不会把它移出待办，提交答复后才移出。已答复、取消、过期或真正停用的对话不出现在此处；仅归档不会关闭有效任务。点击卡片定位原对话和消息；每次最多加载 30 项，可以继续加载。

普通通知没有答复要求，不自动变成待办。应用要继续跟踪已答复的任务，通过原有 `getTaskCard` / `updateTaskCard` 更新处理状态。

## 会话管理

- 搜索框匹配对话名称或应用名称，支持对话、待办和归档分类。
- 手机长按对话或对话标题，电脑使用操作按钮，可置顶、改名、归档、恢复或删除。
- 置顶保存在服务器，登录其他设备也可见。
- 改名保留会话 ID、稳定登记键、历史、图片、任务和唤醒绑定。旧网页链接仍然有效；微信手写标签使用新名称，最新标签通过 `/chats` 或 `listConversations` 查询。
- 同一应用下有效对话不能重名；仅归档仍是有效对话，历史停用状态取消归档后也不会自动恢复通信。

## 草稿

文字回复、卡片选项、表单内容，以及发送结果不明确时的原请求 ID，保存在当前浏览器的 `localStorage`，以服务和微信归属隔离。刷新或关闭后再次打开可恢复；提交成功、删除对话或主动退出登录会清理。草稿最长保留 30 天，不跨设备同步。

浏览器清理网站数据、禁用存储或空间不足会影响恢复；保存失败会显示提示。草稿以明文保存在浏览器，请在本人设备使用；服务器消息记录仍沿用加密存储。未发送图片预览暂不持久化，离开页面会提醒。

发送结果未确认时，重试沿用同一请求 ID 与内容；表单也不能在重试过程中改决定。只有服务器确认提交成功才清理该草稿。

## 轻量表单

服务端 1.13.0、插件 1.8.0 支持 `sendTaskCard(mode="form", fields=[...])`。建议 2–3 个字段，最多 5 个；支持文本、下拉选择、数字、日期，字段可选填。不要把简单确认扩展成表单；原通知和四种卡片类型保持原默认行为。

表单答复经过同一个收件箱与回调机制返回应用，`task_response.field_values` 使用字段 ID 作为键；数字和日期以字符串传递，避免数字精度丢失。详见 [任务卡片协议](server/TASK-CARDS.md)。

页面复用现有 Element Plus 的表单与日期控件。选择项先填入当前浏览器草稿，点击提交后才发送；取消不会提交决定。管理端与手机端共用任务组件，但保持各自认证和草稿范围。

## 微信排版

结构化提醒按标题、情况、需要处理事项分层；卡片展示类型、选项或字段、截止时间与手机页入口。帮助、状态和列表也使用统一的 Markdown 层次。`sendMessage` 保留调用者原正文；完整历史和原有去重依据不会因展示样式升级而改变。

普通通知不要求任务交互；任务组件只在需要时渲染，不宣称按网络分包加载。自动唤醒由外部宿主另行配置和验收。
