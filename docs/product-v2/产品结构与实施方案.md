# Notify Bridge 产品结构与实施方案

候选 v0.2 / 2026-10-14。本方案供产品结构与操作体验评审；未确认为正式需求，未改变业务实现。

## 定位与工作起点

Notify Bridge 是统一消息中转服务站。外部 Codex、Claude Code、服务器任务和业务程序通过 API/MCP 接入；站内负责通信平台连接、鉴权、路由、格式转换、收发与记录。Codex 可依据仓库资料在站外协助部署、维护及指导使用，不是站内 Agent。宿主接收器/事件订阅向外部调用方递交事件，不改变这个职责边界。

管理员的三个主要触发是：让新程序使用已有连接、连接一个新平台账号、根据失败通知定位原投递。导航与批次围绕这三个任务组织，不按密钥字段、接口数量或内部包目录组织。

## 四类对象及现有映射

| 产品对象 | 当前实现与关系 | 管理位置 / 边界 |
|---|---|---|
| 接入应用 | 复用 api_clients 调用方身份；Key 是认证凭据，不是独立应用。一个身份可有多个会话，一个身份当前只维护一把有效 Key | 接入应用：名称、启停、允许连接、默认连接、接入资料、密钥生命周期。AI/业务系统是资料选项，暂不新增强制持久分类 |
| 通信连接 | 复用 Bot 与 bot_id；平台是连接类型，一个连接对应独立微信账号或飞书应用和本人接收账号 | 通信连接：建立、绑定/配置、启停、测试。原平台能力与数据沿用，不自动更换身份或平台 |
| 投递规则 | 当前已有 Key 的 bot_ids/default_bot_id，加上请求显式 bot_id/channel 及权限检查 | 在接入应用中显示“允许连接与默认投递”，在详情保留原投递连接；本阶段不新增规则表、规则引擎、自动广播或备用路由 |
| 消息与回复 | 沿用 outgoing/channel_outgoing、inbox、chat_messages、会话与任务记录；按调用方、会话及 Bot 关联 | 消息：投递记录与回复两个视图。会话是组织上下文；任务卡片与答复是消息下的扩展，手机页保留其处理能力 |

省略 bot_id：使用应用默认连接；没有默认但只有一个授权连接时使用唯一连接；有多个候选时返回 bot_required。授权连接及默认连接不是凭据本身，配置文件中的路由偏好不赋予权限。改变默认连接不改变旧回执的原 bot_id；跨应用、跨连接去重边界保持。

## 候选导航

保留“总览、消息、接入应用、通信连接、设置与帮助”五项。暂不单列“投递规则”：当前规则很少，离开所属应用会增加寻找与配置成本。

| 导航 | 核心任务 / 主要内容 | 从旧界面迁入 |
|---|---|---|
| 总览 | 找到失败/未知投递，看到应用和连接数量，开始接入/建连接 | 新增只读摘要，复用既有状态；统计口径以实际查询范围为准，不假造送达率 |
| 消息 | 用应用、连接、去重键定位通知，核对状态、原因及关联回复 | 新管理入口。现有 caller-scoped /api/deliveries 和手机历史不足以直接支持管理员全局查询 |
| 接入应用 | 建立身份 → 授权 → 获取配置与使用资料 | “接入密钥”与“开发者文档”的配置导出向导合并；密钥操作保留在应用详情，避免列表堆积 |
| 通信连接 | 添加/配置平台连接，管理启停，核对收发与测试 | Bot 管理、二维码/飞书配置。绑定进度与投递结果分开显示 |
| 设置与帮助 | 三个子页：代理与节点、账号与安全、使用与帮助；侧栏提供代理/安全直达 | 保留完整代理管理与节点操作；账号安全为新增候选；三条交付路径、手机登录及文档归入帮助 |

原型展示主要流程，并补齐代理/节点、管理登录/改密/找回/换绑。已有改名、密钥重置/停用/删除、Bot 删除、代理订阅/节点/检测、手机登录、图片/任务/草稿/归档等能力全部列为保留，不因未演示就移除。不可逆删除仍单独确认，密钥轮换明确旧凭据失效和外部调用方重配。

## 三条原型流程及隐藏规则

**接入应用：** 管理员为一个外部调用方输入符合现有规则的名称，选择资料使用方，授权通信连接并选择默认；核对后创建，直接获得配置/使用说明。无可用连接时先建连接，回来保留应用草稿。取消不创建，保存失败保留输入、不显示成功；已有应用允许零授权以暂停通信，新增向导以至少一个可用连接完成可用接入。空白默认值、唯一连接与多连接显式指定的语义分开。已有 Key 不回显；远程资料不携带 Key，本机/HTTP 私有配置由本人保存。原型下载仅演示 JSON/Markdown，不等同真实插件 ZIP。

**通信连接：** 管理员选择微信/飞书，配置/绑定本人账号；飞书回调与卡片回调使用该 Bot 的同一地址，完成平台发布；显式发一次测试，保留原连接与回执，再核对手机收件和回复。初次创建后保留“待配置”连接，取消后可从列表续接；发送失败和未知不是配置成功。原型保留已创建连接和已发测试记录；取消测试窗口不删除投递记录，完整配置后可返回应用授权。测试结果未知时禁用再次测试，先查原结果；具体人工再发权限需单独设计，不能换键绕去重。停用暂停后续调用和后台收发，历史保留。

**查询投递：** 管理员从总览进入失败/未知列表，按应用、连接、记录 ID 或原 dedup_key 查找，打开详情核对权限校验/平台阶段、错误分类和后续建议，查看关联回复或复制无正文排查信息。无数据、筛选无结果、读取失败分开。平台已接受不是手机已送达，无回复不是未送达；prepare failed 不硬判限额耗尽。旧记录缺诊断明确“无历史诊断”，不补造。

## 代理与节点：完整管理流程补正

代理是站点级宿主回调出站基础能力；不是微信/飞书 Bot，也不是给每个应用自动配置一套节点。微信/飞书的收发保持当前直连机制。仅针对已授权回调主机使用代理，不因节点失败自动回退直连。

管理员从侧栏“代理与节点”进入，先看当前实际出口、模式、最后完整检测和故障；查看订阅流量/到期、成功更新时间及下次更新。节点列表提供名称/协议/延迟/UDP、搜索与固定节点选择。选择只形成草稿，点击“应用选择”才检测完整回调链并更新出口；延迟探测成功不代表回调成功。

- 自动：按优先组依次尝试，同组关键词全部匹配，再在组内尝试节点。手动：固定选定节点，失败不暗中选另一个节点。
- 应用/订阅更新失败：保留或恢复原模式、节点与可用配置；恢复也失败时实际出口标“未确认”，停止继续改配置，保留诊断并人工检查。
- 订阅地址密码输入、留空保留、不回显；只导入 Clash/Mihomo YAML 节点，不导入订阅自带监听/规则。间隔、优先组及自动管理在设置弹窗渐进展开。
- 关闭自动管理只暂停更新/检测定时任务，不停止代理进程或当前出口。手动更新仍可执行。首次未配置、订阅无节点、无搜索结果、读取失败、下载失败、节点均不可用、优先组回退及控制/回退失败均有候选场景。

原型完成模拟操作，复用现有字段语义；静态展示的流量、节点和延迟不是真实检测。今后主要工作是现有能力归位及前端调整，不需要更换 API/数据库或另建节点中心。

## 账号密码与恢复：新增候选

按用户本轮要求增加账号密码登录、使用旧密码修改密码、忘记密码验证码找回，以及服务器权限兜底。继续单管理员，不顺带增加多用户角色系统。首次账号初始化沿用现有管理员认证或受授权的服务器初始化流程，禁止部署原型公开示例口令；可先配置连接再验证绑定恢复账号，避免未有 Bot 就无法完成首登的循环。旧管理员 Key 的迁移/撤销及必要机器维护入口须在批次 5 明确，不偷偷失效旧接入。当前稳定服务仍使用管理员 Key，不能把密码做成原 SHA-256 Key 的改名；新密码使用适合低熵密码的带盐密码哈希，新管理会话采用受保护的服务端认证机制。技术合同与迁移策略在实施批次中明确。

| 流程 | 谁核对什么 / 做什么 | 结果与边界 |
|---|---|---|
| 正常登录 | 管理员输入账号、密码；错误统一反馈 | 成功进入管理中心；限制猜测，不在浏览器长期存密码；应用 API Key 是独立调用身份 |
| 旧密码改密 | 已登录管理员再验证旧密码，输入两次新密码 | 原密码错误不修改；成功使旧管理会话失效并要求正常登录；不动消息库、Bot 凭据或应用 Key |
| 绑定或换绑恢复账号 | 先验证旧密码，选已配置连接；验证码固定发到该连接的既定本人身份，由新通道验证码验真 | 原绑定在验证完成前继续有效，成功后原保护才释放；不是仅选一个 Bot 名称就建立恢复信任 |
| 忘记密码 | 输入管理员账号；服务端固定到预先验证的恢复账号发送验证码，不接受新收件人/新 Bot | 统一反馈，验证码短时有效、一次使用、有限尝试和发送频率；核验仅取得限时重置资格，不自动登录 |
| 设置新密码 | 已核验恢复资格输入两次新密码 | 原密码、旧管理会话及未使用恢复码失效；正常登录后继续，通知重置事件而不发送密码 |
| 服务器兜底 | 经授权的服务器操作者确认目标实例与管理员身份，备份管理员状态，受控终端交互设置新密码 | 服务器专用工具只改管理哈希/会话版本，撤销旧恢复码；保留数据、主密钥、Bot、应用 Key 与已验证恢复绑定；不在 Web 暴露远程绕过认证入口 |

恢复保护覆盖绑定期间的 Bot 停用/删除、平台/本人身份替换、绕过验证的重新绑定；后端各入口必须统一阻止，不能只禁用一个前端按钮。正常凭据更新可在身份不变且必要核验下处理。新通道验证前禁止释放旧通道；验证码不能通过普通应用 API 或公共会话历史读取，需服务内部保留通道发送且不产生可读取的敏感正文。

Bot 不能关闭只保护站内操作，不能保证微信上下文、飞书凭据、网络永不失效。恢复通道掉线仍有服务器兜底。无服务器权限又收不到验证码时不放行重置，也不重新生成加密主密钥。

**当前没有账号密码重置 CLI。** 未来在同一服务栈增加服务器专用维护入口，默认预览，执行需身份/实例确认和授权，密码不作为命令参数、不打印日志；修改原子落盘，旧会话/码撤销且可验证。若迁移或部署需短暂重启，单独安排维护窗口，本轮不执行。当前 Key 丢失也不能逆算明文，现行管理员 Key 替换需走现版本受控维护，不用“删库/重新初始化”解决。

登录原型示例为 admin / NotifyBridgeDemo123!，验证码固定为 246810；内存状态仅演示，刷新重置。15–128 字符、5 分钟验证码和 60 秒冷却是候选演示参数，实施时按统一策略确认并验证，不从 mock 自动冻结字段/接口。密码恢复原则参考 [OWASP Forgot Password](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) 与 [Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)。

| 4 代理与节点管理闭环 | 检测异常/更新订阅 → 选择模式与节点 → 完整回调检查 → 应用或保留旧配置 → 故障续办 | 复用 Proxy.vue、proxy config/update/check/select、已有代理服务；调整布局与入口，不新建代理控制体系 | 手动失败不跳节点，自动按组回退；选中未应用不改出口；订阅秘密不回显、空白保留；更新/切换失败恢复旧配置，回退失败标未知；暂停自动管理不停止代理 |
| 5 管理登录与账号恢复闭环 | 账号登录 → 旧密码改密 → 本人恢复绑定/换绑 → 验证码找回 → 无通道时服务器重置 | 新管理认证、会话、密码哈希、恢复挑战与绑定保护，服务器专用工具；定点迁移旧管理员 Key。应用鉴权不混用 | 错误/限流/取消不改密；验证码过期/用过/跨用途拒绝；不得由请求指定接收人；改密/重置撤销旧管理会话；Bot 后端全部入口保护；换绑先验真；服务器重置不动消息/主密钥/应用 Key；隔离环境实际演练 |
| 6 维护与帮助交付 | 部署者或用户选路径 → 找到资料 → 维护/接入/故障步骤 → 独立实例验证 | 现有文档/开发者资料包、代理及手机登录入口归位；补正文档冲突；不重写现有手机页 | 三条路径互不混用；秘密不进源码资料；从交付包干净解压可用；升级前一致备份/隔离恢复；生产上线必须另授权 |

每批均是可使用的完整流程，不先做完所有“列表”再做所有“接口”。生产回归覆盖关联面，改动保持局部；既有受保护功能先记录基线。设计确认后才详细核实各批 API/数据影响，不以原型 mock 字段冻结接口。各批在独立开发环境完成；上线计划另行提出。

## 需要决定的一个关键业务问题

1. **管理员是否可以查看消息/回复正文？** 建议默认仅状态、错误分类和定位信息；确需正文时提供明确的按需入口并限制记录。现有手机本人历史不等于管理端自动获得全局正文读取权限。原型中摘要/回复均是虚构，未据此决定生产权限。
现有授权、默认路由、未知结果不自动重发均继续沿用，不要求再次确认，也不在本轮引入补发/广播/备用连接。
