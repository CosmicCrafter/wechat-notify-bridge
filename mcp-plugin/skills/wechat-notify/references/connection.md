# 接入、唤醒与心跳

远程模式使用 Streamable HTTP 与 OAuth，由用户在网页登录并选择身份；工具不能代替批准 OAuth。本机 stdio 使用用户保存的私有配置，密钥来自微信 `/getkey 名字` 或 Admin。选择一种接入，避免同名工具重复加载。

缺工具时检查插件连接与宿主加载状态，必要时刷新连接或重新打开聊天。先 getCallerIdentity 检查身份；除非用户要求，不以发送测试消息代替状态查询。不在聊天索取或展示密钥、访问令牌、手机登录码。

## 自动唤醒

工具自身不会唤醒 AI。桌面接收器需要显式绑定宿主聊天；云端事件需要宿主支持并订阅对应 conversation_id。微信和手机网页消息均可进入已配置的唤醒通道，但入库不证明宿主已自动运行。

排查顺序：核对会话 ID → 用户实际使用的标签/手机会话 → 按需查收件 → 接收器或事件订阅状态 → 宿主运行证据。当前 9 个 MCP 工具没有启用唤醒工具，不虚构调用，也不拿定时器冒充接收器。不承诺桌面宿主退出后仍能唤醒。

## 空闲心跳

服务器连续 12 小时无有效微信收发时尝试心跳，正常沟通顺延；心跳本身发送成功也计入活动，重启保留计时。查询、读取历史、网页访问/回复、重复请求和失败发送不刷新微信活动或 context_token。

心跳不能保证会话永久有效；报告过期后应恢复连接。插件不创建额外定时任务，不使用服务器保留的 server-heartbeat- 去重键前缀。
