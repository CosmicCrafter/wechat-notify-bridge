# 会话登记、路由与归档

每个 AI 客户端使用独立身份，同一客户端可以登记多个聊天。密钥下的聊天数量不等于宿主窗口数；同一密钥内的 conversation_id 是路由边界，不是权限隔离边界。

保存 client_id、conversation_key、conversation_id、name 和 reply_tag。同一 key 重试复用原登记，不改名、不自动恢复归档。用户继续已有任务时复用原 ID。

忘记 ID 时可用已保存的稳定 conversation_key 重新登记；不要按相似名字接管其他聊天。若稳定 key 和 ID 都遗失且无法确认对应关系，向用户澄清，不新建同名会话掩盖问题。

微信标签由服务器生成：一个有效聊天显示 `[codex]`，多个显示 `[codex-通知桥]` 等。返回的 reply_tag 是准确回复标签，微信 `/chats` 可查。手机会话页直接回复无需标签。未知或含糊标签进入公共收件箱，不自动作为当前任务授权。

## 归档与恢复

- 用户结束任务或通知订阅时，setConversationActive(id, false) 归档并保留历史；不要每轮自动归档。
- 用户继续任务时，setConversationActive(id, true) 恢复原 ID。
- 有效会话名称唯一，归档会话可以重名。恢复遇到 conversation_name_conflict 时，说明是哪两个会话冲突，让用户决定保留哪个有效；未获明确指示不得归档另一个聊天。用户可在手机页长按归档冲突会话后恢复旧会话。
- 当前 MCP 和手机页面没有会话改名工具；Admin 的客户端改名不是会话改名。不得编造改名调用或新建 ID 绕过恢复冲突。
- 归档会话不可收发，但历史与图片可读；删除会话会清理消息和附件，不能重新登记相同 key 来假装恢复删除的数据。
